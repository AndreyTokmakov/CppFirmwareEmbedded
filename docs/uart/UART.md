# UART — подробное руководство для начинающих

UART (Universal Asynchronous Receiver-Transmitter) — один из самых простых и самых популярных способов обмена данными между электронными устройствами. Если вы начинаете изучать микроконтроллеры (ESP32, STM32, Arduino, Raspberry Pi Pico и др.), то практически сразу столкнетесь с UART.

После прочтения этой статьи вы будете понимать:

* что такое UART;
* как он работает;
* зачем нужны линии TX и RX;
* что такое baud rate;
* как выглядит передача данных;
* как подключать устройства;
* какие ошибки возникают чаще всего.

---

# Что такое UART

**UART (Universal Asynchronous Receiver-Transmitter)** — это аппаратный модуль микроконтроллера, который умеет:

* преобразовывать байты в последовательность битов для передачи;
* принимать последовательность битов и собирать их обратно в байты.

Сам UART **не является протоколом сети**, как Ethernet или Wi-Fi.

Это всего лишь способ передать данные между двумя устройствами по нескольким проводам.

Например:

```
ESP32  <--------UART-------->  GPS-модуль
```

или

```
Компьютер
      │
 USB-UART адаптер
      │
 ESP32
```

---

# Почему UART называется последовательным интерфейсом

Данные передаются **по одному биту за раз**.

Например, нужно передать букву:

```
'A'
```

В памяти компьютера она занимает один байт:

```
01000001
```

UART не отправляет сразу все 8 бит.

Он передает их последовательно:

```
0
1
0
0
0
0
0
1
```

Именно поэтому интерфейс называется **последовательным (Serial)**.

---

# Асинхронная передача

Самое важное свойство UART — он **асинхронный**.

Это означает, что между устройствами **нет отдельной линии синхронизации (Clock)**.

Например:

SPI использует

```
CLK
```

I²C использует

```
SCL
```

UART ничего подобного не имеет.

Вместо этого оба устройства заранее договариваются:

> "Будем передавать данные со скоростью 115200 бит/сек."

После этого каждое устройство самостоятельно отсчитывает время передачи каждого бита.

---

# Из чего состоит UART

Практически любой UART имеет три основных вывода.

```
TX
RX
GND
```

### TX (Transmit)

Передает данные наружу.

```
ESP32
 TX ─────────►
```

---

### RX (Receive)

Принимает данные.

```
◄──────── RX
ESP32
```

---

### GND

Общий провод.

Без общей земли связь часто работать не будет.

---

# Как соединяются два устройства

Правильное подключение выглядит так:

```
     ESP32                     GPS

TX ------------------------ RX

RX ------------------------ TX

GND ---------------------- GND
```

Новички часто совершают ошибку:

```
TX → TX
RX → RX
```

Так работать не будет.

Всегда:

```
TX → RX

RX → TX
```

---

# Как UART передает данные

Предположим, необходимо отправить символ:

```
'A'
```

Его код:

```
65
```

В двоичном виде:

```
01000001
```

Но UART передает не просто байт.

Передача выглядит так:

```
Старт

↓

0

Данные

↓

10000010

Стоп

↓

1
```

Или более наглядно:

```
| Start | b0 | b1 | b2 | b3 | b4 | b5 | b6 | b7 | Stop |

    0      1    0    0    0    0    0    1    0     1
```

Обратите внимание:

UART обычно передает **младший бит первым (LSB first)**.

---

# Что такое Start Bit

Пока данные не передаются, линия находится в состоянии:

```
1
```

Это называется **Idle**.

```
───────────────
111111111111111
```

Когда начинается передача,

UART переводит линию в

```
0
```

Получатель понимает:

> "Начинается новый символ."

---

# Что такое Stop Bit

После передачи данных линия возвращается обратно в состояние

```
1
```

Получатель понимает:

> "Передача символа закончилась."

---

# Что такое Baud Rate

Очень важный параметр UART.

Baud Rate показывает,

**сколько бит передается за одну секунду.**

Например

```
9600 baud
```

означает

```
9600 бит/сек
```

Самые популярные скорости:

| Скорость | Где используется          |
| -------- | ------------------------- |
| 9600     | GPS                       |
| 19200    | Старые устройства         |
| 38400    | Промышленное оборудование |
| 57600    | Микроконтроллеры          |
| 115200   | ESP32, STM32, Arduino     |
| 230400   | Быстрая передача          |
| 460800   | Высокая скорость          |
| 921600   | Очень высокая скорость    |

Если скорости не совпадают:

```
Передатчик:

115200

Получатель:

9600
```

то данные превращаются в "кракозябры".

# Формат передачи

Очень часто можно увидеть запись:

```
115200 8N1
```

Разберем ее.

### 115200

Скорость передачи.

---

### 8

Передается

```
8 бит данных
```

---

### N

Parity отсутствует.

Возможные варианты:

```
N
```

нет проверки

```
E
```

четная

```
O
```

нечетная

---

### 1

Один стоп-бит.

---

Таким образом

```
115200 8N1
```

означает:

```
115200 baud

8 бит данных

без parity

1 stop bit
```

Это самый распространенный формат.

# Полный и полудуплексный режим

UART обычно работает в **полном дуплексе (Full Duplex)**.

Это означает:

```
TX

→→→→→→→→

RX

←←←←←←←←
```

Два устройства могут одновременно отправлять данные друг другу.

Это возможно потому, что используются две отдельные линии:

* TX — для передачи;
* RX — для приема.

Если же по какой-либо причине используется только одна линия для обмена, связь становится **полудуплексной (Half Duplex)**: в каждый момент времени данные идут либо в одну сторону, либо в другую.

# Где используется UART

Практически везде.

Например:

```
ESP32 ↔ Компьютер

STM32 ↔ GPS

Arduino ↔ Bluetooth

Raspberry Pi ↔ GSM

ESP32 ↔ RFID

STM32 ↔ LoRa
```

Очень многие модули используют именно UART.

---

# UART на ESP32

Большинство плат ESP32 имеют несколько аппаратных UART.

Например:

```
UART0

UART1

UART2
```

Обычно:

* **UART0** используется для загрузки прошивки и вывода сообщений в последовательный монитор (Serial Monitor).
* **UART1** и **UART2** можно использовать для подключения внешних устройств — GPS, модемов, датчиков, RFID-считывателей и т. д.

На ESP32 выводы UART можно переназначать практически на любые GPIO благодаря встроенной матрице ввода-вывода (GPIO Matrix), что делает работу с несколькими последовательными устройствами очень гибкой.

---

# Преимущества UART

* Очень прост в использовании.
* Требует минимум проводов.
* Поддерживается практически всеми микроконтроллерами.
* Не требует общего тактового сигнала.
* Подходит для отладки и обмена данными между двумя устройствами.

---

# Недостатки UART

* Обычно рассчитан на связь только между двумя устройствами.
* Нет встроенной адресации устройств, как в I²C.
* Нет встроенного механизма подтверждения доставки данных.
* На больших расстояниях чувствителен к помехам (если используются обычные TTL-уровни).
* Скорость передачи ограничена качеством соединения и характеристиками оборудования.

---

# Сравнение UART, SPI и I²C

| Характеристика         | UART            | SPI                     | I²C                |
| ---------------------- | --------------- | ----------------------- | ------------------ |
| Тактовая линия         | Нет             | Да                      | Да                 |
| Тип передачи           | Асинхронная     | Синхронная              | Синхронная         |
| Минимум проводов       | 3 (TX, RX, GND) | 4 (MOSI, MISO, SCK, CS) | 2 (SDA, SCL) + GND |
| Несколько устройств    | Обычно нет      | Да                      | Да                 |
| Полный дуплекс         | Да              | Да                      | Нет                |
| Простота использования | Очень высокая   | Средняя                 | Средняя            |

---

# Итоги

UART — это базовый последовательный интерфейс, который позволяет двум устройствам обмениваться данными без отдельного сигнала синхронизации. Его простота, универсальность и широкая поддержка сделали его стандартом де-факто для подключения периферии к микроконтроллерам.

Для большинства проектов на ESP32 или STM32 именно UART становится первым интерфейсом, с которым знакомится разработчик: через него загружается прошивка, выводятся сообщения отладки и подключаются внешние модули. Освоив принципы работы UART, вы значительно легче поймете и другие интерфейсы обмена данными, такие как SPI, I²C, CAN и USB.
